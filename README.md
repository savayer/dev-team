# AI-команда разработки для Claude Code

```
Владелец ↔ head-pm (основная сессия)
              ├── backend-lead  ── senior-engineer / middle-engineer
              ├── frontend-lead ── senior-engineer / middle-engineer / ui-tester
              ├── qa-lead       ── senior-engineer / middle-engineer / ui-tester
              └── reviewer      (только чтение, перед коммитом)
```

## Что внутри

| Файл | Зачем |
| --- | --- |
| `.claude/agents/head-pm.md` | PM: планирует, раздаёт лидам, принимает работу, один итоговый отчёт с вопросами |
| `.claude/agents/*-lead.md` | Лиды отделов: декомпозиция, раздача инженерам, ревью, интеграция |
| `.claude/agents/senior-engineer.md`, `middle-engineer.md` | Исполнители, дальше не делегируют |
| `.claude/agents/reviewer.md` | Независимое ревью диффа ветки перед коммитом, режим security для auth/платежей/ПДн. Ничего не правит |
| `.claude/agents/ui-tester.md` | Смоук в браузере через Playwright MCP (поднимается из frontmatter агента через `npx`) |
| `.claude/skills/team-protocol/SKILL.md` | Общий протокол: стоп-лист, неясности, зависимости, миграции, документация, память, формат отчёта. Предзагружается лидам и инженерам |
| `.claude/skills/api-contract/SKILL.md` | Шаблон контракта бэк ↔ фронт |
| `.claude/skills/auth-safety/SKILL.md`, `integrations/SKILL.md` | Проверки для auth/прав и вебхуков. У backend-lead и reviewer |
| `.claude/skills/design-system/SKILL.md` | Шаблон дизайн-системы — заполни под проект |
| `.claude/settings.json` | Глубина вложенности 2, запрет push/публикации/деплой-команд, `--no-verify` и чтения `.env` |
| `.claude/CLAUDE.md` | Границы команды (стоп-лист) — их видит классификатор режима `auto`. Корневой `CLAUDE.md` проекта не трогает |

## Установка

1. Обнови Claude Code (`claude update`). Нужна версия, где субагенты могут запускать своих субагентов (по умолчанию до 3 уровней — с v2.1.219).
2. Скопируй `.claude/` в корень проекта. Если там уже есть `settings.json` или `CLAUDE.md` — слей вручную.
3. Проверь `CLAUDE.md` проекта по разделу «Что должно быть в CLAUDE.md проекта» ниже. Если есть фронт — заполни `.claude/skills/design-system/SKILL.md`.
4. Режим без вопросов. В **пользовательский** `~/.claude/settings.json` (из проектного файла `auto` игнорируется):
   ```json
   { "permissions": { "defaultMode": "auto" } }
   ```
   Или запускай с `--permission-mode auto`. `acceptEdits` для этой схемы непригоден: каждая Bash-команда каждого инженера — запрос тебе. Без `auto` — `bypassPermissions`, и только в изолированном контейнере.
   Учти: в `auto` запись памяти лидов (`.claude/agent-memory/`, защищённый путь `.claude`) проходит через классификатор, а после 3 блоков подряд или 20 за сессию auto встаёт на паузу и начинает спрашивать.
6. Открой проект в `claude` интерактивно и подтверди доверие к папке — иначе inline MCP у `ui-tester` не поднимется (в `-p` автодоверие не считается).
5. Запуск (после шага 6 при первой установке):
   ```bash
   claude --agent head-pm
   ```
   Можно сделать PM сессией по умолчанию: `"agent": "head-pm"` в `.claude/settings.local.json` (не в общем `settings.json`). Тогда для обычной работы — `claude --agent claude`.

## Что должно быть в CLAUDE.md проекта

Строго обязательного нет: без CLAUDE.md команда работает — PM находит команды в `package.json`/`Makefile`/README и фиксирует их в `.team/plan.md`. Но с ним точнее и дешевле:

1. **Команды проверки** — установка (та, что не переписывает лок: `npm ci` и аналоги), тесты, линтер, типы, сборка. Самое важное: на них держатся VERIFIED и приёмка.
2. **Если есть UI** — команда локального запуска, URL, тестовый вход (без реальных секретов). Без них `ui-tester` проверит только то, что доступно без входа.
3. **Желательно** — образцовые файлы (сервис, эндпоинт, компонент, тест), стек, структура.

Пример:

```markdown
## Команды
- Установка: `npm ci`
- Тесты: `npm test` · Линтер: `npm run lint` · Типы: `npm run typecheck` · Сборка: `npm run build`
- Запуск: `npm run dev` → http://localhost:3000, тестовый вход: `npm run seed` создаёт demo@example.com
```

## Как пользоваться

Пишешь PM задачу как обычно и уходишь. По ходу он тебя не дёргает: неясности решает сам, решения пишет в `.team/decisions.md`. В конце — один отчёт с разделом «Вопросы к тебе», где у каждого вопроса уже выбран вариант по умолчанию. Отвечаешь коротко: «1 — да, 3 — вариант Б», и PM раздаёт доработки.

`.team/decisions.md` имеет смысл коммитить — это журнал решений команды.

## Настройка

- **Сеньорность = модель + effort + размер задачи**, а не персона в промпте. Сейчас лиды и senior на `opus`, middle на `sonnet`. Дорого — переведи senior на `sonnet` и поставь лидам `effort: medium`.
- **Новый отдел** (DevOps, mobile, data): скопируй `backend-lead.md`, поменяй `name`, `description`, «Зону» и «Кому что», убери backend-специфику (контракт, миграции, auth/integrations). Затем добавь отдел в `Agent(...)` и первый абзац `head-pm.md`, строку «Иерархия» в `team-protocol`, схему в начале README.
- **Знания стека** (конвенции API, дизайн-система, работа с вашей БД) — отдельными скиллами в `.claude/skills/` и в поле `skills:` нужным агентам. Пиши их по своему коду: только то, что не видно из кода и отличается от дефолтов (паттерны, грабли, запреты), ориентир — до 60 строк. Language-специалистов из готовых коллекций не копируй — это пересказ языка, который модель и так знает.
- **Деплой-команды проекта.** Если у проекта есть свой CLI деплоя (`vercel --prod`, `fly deploy`, `railway up` и т.п.) — добавь его в `permissions.deny`.
- **Конфликты файлов.** Параллельные инженеры в одних файлах затирают друг друга, поэтому лиды раздают непересекающиеся файлы. Для полной изоляции можно добавить инженерам `isolation: worktree`, но worktree ответвляется от основной ветки, а не от текущей, и слияние ляжет на лида.

## Важно знать

- `--agent head-pm` заменяет стандартный системный промпт Claude Code на промпт PM. Для оркестратора это нормально; для обычной работы запускай просто `claude`.
- Каждый уровень — отдельные контексты и токены. На мелочи PM делает сам или берёт одного лида (это прописано в его промпте).
- `ui-tester` при первом запуске тянет `@playwright/mcp` через `npx`; если браузер не скачался сам — `npx playwright install chromium`.
- Плагины-коллекции агентов (например, VoltAgent) лучше не ставить глобально: лиды запускают агентов через `Agent` без списка и увидят их все. Ограничение «лид запускает только своих инженеров» держится на промпте: `Agent(...)` в frontmatter субагента не работает, а `Agent(...)` в `permissions.deny` отключил бы этих агентов и в твоих обычных сессиях в проекте.
- Deny-правила Bash — страховка, а не граница безопасности: другие формы вызова (`/usr/bin/git push`, `sh -c '…'`) их обходят. Основная преграда в `auto` — границы команды в `.claude/CLAUDE.md`, их видит классификатор. Для жёсткой гарантии — PreToolUse-хук по regex полной команды или песочница.
- Твой пользовательский `~/.claude/CLAUDE.md` грузится во все агенты команды. Протокол говорит им ставить командные правила выше, но большой глобальный файл всё равно ест контекст каждого запуска.
- `-p` (headless) режим тоже работает с вложенными субагентами, но там запускающий субагент не ждёт фоновых детей — для этой схемы лучше интерактивная сессия.
- Альтернатива — agent teams (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, экспериментально): лиды становятся teammates и общаются друг с другом напрямую. Teammates не могут создавать своих teammates, но могут запускать субагентов, так что инженеры остаются субагентами лидов.
